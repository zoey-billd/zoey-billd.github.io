# Container Habitat Generator

## 项目概览

这个项目是一个 Houdini 模块化掩体与垂直通行结构生成器。它不是随机摆放箱子，而是把箱体、平台、栏杆、梯子、支撑和场景装饰整理成可以单独检查的结构分支，再合并成可交付的完整场景。

当前版本已经从早期 blockout 推进到交付包整理：保留英雄视角、正面视角、软件视口截图和分模块录屏，用来展示遮挡轮廓、垂直路线、模块拆分和下游继续接 UE 的可能性。

## 一句话流程

```text
视觉目标与比例 -> 箱体布局 -> 遮挡与路线 -> 结构分支 -> 支撑修正 -> 合并输出 -> 交付检查
```

## 设计目标

- 让堆叠箱体、遮挡关系、垂直路线、栏杆和支撑在正面与三分之四视角下都保持可读。
- 把 container、access、support、dressing 等结构系统拆成分支，避免所有几何只停留在单一合并结果。
- 在合并前保留模块检查入口，方便单独查看箱体主体、通行结构、支撑杆和地面装饰。
- 输出时保留组件、楼层、路线、材质等语义信息，为后续筛选、材质替换和 UE 侧二次处理预留接口。

## 主要控制维度

- 楼层、行列与前后深度决定整体体量。
- seed、错位和悬挑强度决定空间变化，但需要始终回到可读轮廓。
- 平台覆盖、楼梯与梯子控制角色如何在空间中通行。
- 支撑修正和装饰清理用于处理悬挑、杆件穿插、道具遮挡等交付前检查问题。

这些控制项共同决定场景是否读得懂：箱体是否过于平、遮挡是否形成层次、平台之间是否形成路线、悬挑是否有支撑解释，以及顶部轮廓是否足够轻。

## 模块拆分

每个箱体不是一个简单 cube，而是由组件拼装出来：

- 墙体、角柱、波纹加强筋；
- 门板、门锁、把手、通风口、玻璃框；
- 平台、栏杆、立柱、斜撑；
- 梯子、楼梯和少量场景道具。

不同组件会写入结构语义，后续可以按类型单独赋材质、隐藏、导出或调试。公开展示时只保留思路层面的拆分，不展开完整节点链和具体生成规则。

## 技术方案

- 基础生成层负责建立箱体主体、平台、栏杆、梯子、地面装饰和镜头灯光；它更像一个可迭代的场景骨架，而不是一次性的模型摆放。
- 结构分类层根据组件语义把箱体壳体、通行结构、支撑系统和装饰物拆入不同分支；每个分支都能单独检查，便于定位“画面不对”到底来自结构、路线还是装饰。
- 支撑调整层会针对悬挑和平台下方的杆件做轻量修正，让支撑和箱体关系看起来更可信，同时不把底层求解逻辑公开成可直接复制的完整做法。
- 装饰清理层使用精确标记处理影响展示的局部小物件，避免为了清理画面而误删仍然能强化尺度感的桶、草、旗帜或告示牌。
- 输出交付层统一整理法线、结构属性和最终合并结果，让完整场景、模块分支和调试输出都能在作品集录屏中被清楚说明。

## 属性与交付价值

程序化资产不仅要生成形状，还要生成数据。这个项目把模块和结构信息写到几何体上，让后续可以：

- 单独显示某一层的平台、栏杆或支撑；
- 检查悬挑箱体和支撑系统之间的对应关系；
- 快速替换玻璃、金属、箱体墙面等材质；
- 在 UE 中根据属性继续做材质或实例替换；
- 为后续路径连通性检查和交互区域划分预留接口。

## 当前状态与后续计划

当前版本已经能展示模块化掩体与垂直通行结构的骨架、模块拆分和渲染预览，适合作为技术美术作品集中“从环境需求到可交付 HDA”的案例。下一步可以继续补：

- 参数变化对照图；
- 支撑/悬挑 debug 视图；
- 更完整的空间连通性检查；
- UE 中的材质替换与场景落地；
- 道具、灯光和最终镜头包装。
